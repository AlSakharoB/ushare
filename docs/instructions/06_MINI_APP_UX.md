# Mini App: интерфейс и сценарии

## Этап A. Основа интерфейса

Мобильный интерфейс на русском: понятные карточки, достаточные отступы, акцентный цвет, читаемые цифры, светлая/тёмная тема из Telegram. Рабочая ширина 320 px и выше; элементы касания около 44 px; суммы не обрезаются. Использовать viewportStableHeight, safe areas и feature detection Telegram API. Не ставить критическую кнопку под системную панель.

После авторизации показать «Мои чеки», а при ссылке — доступный чек или принятие приглашения. Отсутствует initData → понятный экран «Откройте приложение через Telegram», dev mock не включается автоматически.

## Этап C. Проценты и суммы

Ползунок удобен, но точность обеспечивает поле ввода с 2 знаками. 100% быстрым нажатием не резервировать, если чужие доли уже заняты; предложить «Весь остаток». Показать «Свободно 30%» и «Вы 20%», лимит своего значения = 100% − чужие доли. При конфликте серверный 409 обновляет остаток и объясняет изменение.

Слайдер даёт preview; commit на отпускании/кнопке сохранения, дебаунс и один in-flight запрос. Для нажатий idem key, для абсолютной доли PUT; не отправлять десятки финансовых команд в секунду. Пока mutation pending, не показывать «сохранено». Сервер — источник итогов; frontend preview помечен как предварительный.

Формат сумм `1 234,56 ₽`, ввод принимает запятую/точку и проверяется без float-конверсии денег. Негативные и NaN поля не отправляются. При 0% запись удаляется, позиция остаётся доступна.

## Этап D. Важные состояния

- Loading, empty, offline, timeout, 401, 403/404, 409, 422, rate limit, failed OCR.
- После financial revision показать, что прежнее подтверждение выбора сброшено.
- При возврате к редактированию объяснить: полученные деньги сохраняются, суммы изменятся, возможны доплаты/возвраты.
- В draft участник не видит позиции. Pending invitation не отображается как полноправное участие.
- После close показывается точный purge_at в локальном времени; expiry по серверу, не по часам устройства. При deadline/refetch 404 очистить TanStack Query cache этого чека и изображения, показать недоступность; не использовать persistent client cache для чеков/фото.
- Telegram BackButton и подтверждение потери несохранённых полей. Ввод/клавиатура не закрывают кнопки.
- Участнику с нулевым долгом показывается «Перевод не требуется».

## Этап E. Проверка

Playwright mobile viewports, светлая/тёмная тема, сценарии разных пользователей через раздельные browser contexts. Vitest для парсинга денег/процентов. Проверить реальный Telegram iOS/Android/Desktop отдельно на S11; браузерная эмуляция не доказывает работу WebView. Сохранить screenshots ключевых экранов без приватных данных.
