# Запрос для запуска Codex


---

Реализуй Telegram-бота и Telegram Mini App ReceiptSplit по инструкциям в `docs/instructions/`.

Сначала прочитай существующие AGENTS.md и `docs/instructions/00_README.md`, затем продукт, домен денег, архитектуру, авторизацию, workflow и roadmap. Изучи repository и git status; не перезаписывай чужие изменения. Если проект новый, создай структуру и конфигурацию по S00. Если инструкции пока лежат в другом месте, найди по имени `00_README.md` и аккуратно размести их в `docs/instructions/`.

Выполняй весь план S00–S11 последовательно, а внутри этапов — все шаги. Используй выбранные допущения, не останавливайся на предложении архитектуры или частично работающей версии. После каждого этапа запускай необходимые проверки, создавай Markdown-отчёт по `08_STAGE_WORKFLOW.md`, обновляй PROGRESS и делай локальный атомарный коммит. Кратко сообщай результат, tests и commit SHA, затем продолжай без моего повторного «да».

Особенно соблюдай точные расчёты процентов/скидки/чаевых, сохранение подтверждённых денег при правках, creator-only close, Telegram initData/ACL и удаление через 7 суток. OCR делай реальным PaddleOCR с Cyrillic моделью и benchmark на разрешённых реальных чеках; Qwen3-VL-8B сравнивай при наличии ресурсов. Никаких придуманных метрик.

Когда понадобятся Telegram token, реальные обезличенные фото или недоступное устройство, обозначь конкретную блокировку один раз и продолжай независимые части. Не объявляй незапущенную проверку успешной. Токены и приватные фото не коммить. Не пушить, не публиковать production и не включать платные сервисы без отдельного поручения.

В конце предоставь работающее приложение, воспроизводимый README запуска, отчёт приёмки R01–R13, честный перечень unresolved gates и итоговые коммиты.
