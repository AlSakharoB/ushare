# ReceiptSplit: инструкции для Codex

Версия задания: 1.0. Дата: 03.10.2026. Язык продукта и отчётов: русский.
Цель: реализовать Telegram-бота и Telegram Mini App для распределения расходов по чеку. Это комплект требований и заданий для реализации, а не готовое приложение.

## Как использовать

1. Распакуй комплект в репозиторий в `docs/instructions/`.
2. Если в корне уже есть `AGENTS.md`, аккуратно добавь ссылку на эти инструкции; не перезаписывай существующие правила. Если его нет, можно перенести приложенный `AGENTS.md` в корень, сохранив путь `docs/instructions/`.
3. Передай Codex содержимое `START_CODEX.md` или просто попроси начать S00 по этому комплекту.
4. Выполняй этапы S00–S11 по порядку. Этап завершён только после проверок, отчёта и локального коммита по `08_STAGE_WORKFLOW.md`.
5. Пользователь может поручить один этап либо весь проект. При поручении всего проекта продолжай между этапами самостоятельно; не запрашивай повторное разрешение на обычные изменения и локальные коммиты.

## Приоритет требований

Явные актуальные инструкции пользователя → существующие применимые правила репозитория → `01_PRODUCT.md` → `02_DOMAIN_AND_MONEY.md` → остальные спецификации → задания этапов. Если локальное задание расходится с инвариантами денег или доступа, исправь задание, а не ослабляй инвариант. Существенный конфликт с актуальным запросом пользователя обозначь явно.

## Что нельзя оставлять «на потом»

- Проверку Telegram `initData` на сервере и права доступа на каждом объекте.
- Точную арифметику, защиту от суммарной доли >100%, гонок и двойных запросов.
- Редактирование и ручное создание чеков.
- Явное подтверждение получения денег создателем.
- Удаление закрытого чека через 7 дней, включая зависимые данные и фото.
- Реальные проверки OCR; одних моков недостаточно.

## Осмысленные допущения

По умолчанию RUB, один создатель, проценты с точностью 0,01%, скидка суммой или процентом, чаевые суммой или процентом. Переводы идут вне приложения. Общая ссылка не добавляет человека автоматически: создатель подтверждает его заявку. Чаевые распределяются пропорционально стоимости выбранного. Эти решения можно изменить явным запросом пользователя до реализации соответствующего этапа.
